# ADR-005: Unfold Version and Dependency Strategy

## Status
Accepted

## Date
2026-05-16

## Context
The project uses Django 5.2+ and Python 3.12+. django-unfold v0.93.0 is the latest stable release and requires Django >=5.1. Need to decide on version pinning strategy for pyproject.toml.

## Decision
Use `django-unfold>=0.93.0` (latest stable, allow minor updates). This ensures compatibility with Django 5.2 while allowing bug fix and minor feature updates.

## Alternatives Considered

### Alternative 1: Pin Exact Version
- **Description**: `django-unfold==0.93.0`
- **Pros**: Fully reproducible builds, no surprise breakage
- **Cons**: Misses bug fixes, requires manual update for every patch
- **Why rejected**: Unfollow follows semver for patch releases; minor updates are typically safe and bring useful fixes

### Alternative 2: No Version Constraint
- **Description**: `django-unfold` without version spec
- **Cons**: Major version bumps could break the project
- **Why rejected**: Too risky — Unfold is pre-1.0 and API can change

## Consequences

### Positive
- Gets bug fixes automatically
- Compatible with current Django version
- Matches the project's existing dependency style (e.g., `django>=5.2.1`)

### Negative
- Minor version bumps could introduce UI changes
- Need to test after dependency updates

### Risks
- Unfold breaking changes in minor versions — mitigated by the project's test suite and `manage.py check`

## Implementation Notes
- Add `django-unfold>=0.93.0` to pyproject.toml dependencies
- Run `uv sync` to install
