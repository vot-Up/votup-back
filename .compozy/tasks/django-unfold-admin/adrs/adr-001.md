# ADR-001: Setup Completo com Funcionalidades Avançadas do Unfold

## Status
Accepted

## Date
2026-05-16

## Context
Após a migração de Arquitetura Hexagonal para Service Layer, é necessário verificar visualmente que todos os dados e relacionamentos permanecem intactos antes de trabalhar no frontend. O admin padrão do Django está configurado mas sem nenhum modelo registrado (admin.py vazios). Precisamos de um admin moderno que permita navegação eficiente, busca, e verificação visual completa de todos os modelos.

## Decision
Implementar django-unfold como admin único do projeto com configuração completa: todos os modelos registrados com list_display, search_fields, list_filter, inlines para relacionamentos, ações customizadas, sidebar por domínio, e funcionalidades avançadas (fieldset tabs, compressed fields, command palette, dark mode).

## Alternatives Considered

### Alternative 1: Setup Funcional Primeiro, Evolução Depois
- **Description**: Instalar Unfold com customização básica, deixando features avançadas para iteração futura
- **Pros**: Funcional rapidamente, mais fácil de iterar
- **Cons**: Interface menos polida, precisa de segundo round
- **Why rejected**: O objetivo principal é verificação completa dos dados — funcionalidades avançadas como fieldset tabs e compressed fields facilitam essa verificação e justificam o investimento upfront

### Alternative 2: Setup Mínimo + Dashboard Customizado
- **Description**: ModelAdmins mínimos com dashboard customizado usando Unfold Studio components
- **Pros**: Dashboard dá visão geral imediata
- **Cons**: Dashboard sem ModelAdmins detalhados limita verificação profunda; mais esforço em dashboard = menos em ModelAdmins funcionais
- **Why rejected**: A verificação profunda modelo-por-modelo é mais importante que um dashboard resumo para este momento

## Consequences

### Positive
- Interface moderna e completa para verificação visual de todos os dados
- Sidebar organizada por domínio facilita navegação
- Inlines permitem ver relacionamentos diretamente na página do modelo pai
- Ações customizadas replicam funcionalidades do service layer no admin
- Dark mode e command palette melhoram UX do admin

### Negative
- Mais trabalho upfront na configuração
- Manutenção do admin ao longo do tempo se modelos mudarem

### Risks
- Se modelos mudarem frequentemente, admin precisa ser atualizado — mitigado pelo fato de que modelos são estáveis no projeto
- Unfold é uma dependência adicional — mitigado por ser amplamente usado (900k+ downloads/mês) e ativamente mantido

## Implementation Notes
- Substituir `django.contrib.admin` em INSTALLED_APPS por configuração Unfold
- Usar `unfold.admin.ModelAdmin` como base para todos os ModelAdmins
- Sidebar organizada em 4 seções: Votação, Pessoas, Chapas, Sistema
