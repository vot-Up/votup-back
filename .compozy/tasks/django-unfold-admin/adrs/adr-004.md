# ADR-004: Version History with django-simple-history

## Status
Accepted

## Date
2026-05-16

## Context
The project has django-reversion installed but Unfold has no native reversion integration (PR #90 was closed as wontfix). Using reversion with Unfold would result in unstyled history pages. However, Unfold has native support for django-simple-history via `unfold.contrib.simple_history`, providing a properly styled history experience. The PRD requested version history for audit trail.

## Decision
Replace django-reversion with django-simple-history for admin version tracking. Use `unfold.contrib.simple_history` for integration. Add `SimpleHistoryModelAdmin` as a mixin for business model admins. Enable `SHOW_HISTORY=True` in Unfold settings.

## Alternatives Considered

### Alternative 1: Use django-reversion Without Unfold Styling
- **Description**: Keep reversion, use `reversion.VersionAdmin` directly
- **Pros**: No package change, already installed
- **Cons**: History pages would be unstyled/broken with Unfold, poor UX
- **Why rejected**: Unstyled history pages defeat the purpose of a polished admin

### Alternative 2: Skip Version History
- **Description**: Don't enable any version history in admin
- **Pros**: Simpler setup, no additional package
- **Cons**: No audit trail, can't verify data changes, loses a valuable verification tool
- **Why rejected**: Version history directly supports the verification goal — being able to see what changed and when

## Consequences

### Positive
- Native Unfold integration with styled history pages
- Every model change tracked with timestamp and user
- Can diff between versions in the admin
- Replaces reversion with a better-integrated alternative

### Negative
- Migration from reversion to simple-history requires removing reversion config
- simple-history adds a `_history` table per tracked model
- Existing reversion usage in `core/viewset.py` needs refactoring

### Risks
- simple-history table migration on existing data — mitigated by running `python manage.py migrate` after setup
- Removing reversion may affect existing code that imports it — mitigated by auditing all reversion imports first

## Implementation Notes
- Remove `django-reversion` from pyproject.toml
- Add `django-simple-history` to pyproject.toml
- Add `"simple_history"` to INSTALLED_APPS
- Add `"unfold.contrib.simple_history"` to INSTALLED_APPS
- Remove `from reversion import revisions` in `core/viewset.py`
- Add `SimpleHistoryModelAdmin` mixin to business model admins
- Add `history = HistoricalRecords()` to each business model
- Run `python manage.py migrate` to create history tables
